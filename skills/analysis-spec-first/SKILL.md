# Правило решения до прогона

Вердикт по гипотезе должен получаться подстановкой чисел в заранее записанное
правило, а не из впечатления от результатов. Скил даёт две формы: **спецификацию**
(пишется до расчёта) и **рабочий отчёт** `.run.md` (пишется после).

## Когда применять

- Проверяется утверждение вида «X растёт/падает/различается при условии Z».
- Нужно сравнить периоды, организации, версии документов, варианты метода.
- Результат пойдёт в реестр выводов (скил `insight-registry`).

Для разведки данных без гипотезы спецификация не нужна. Но любой вывод из такой
разведки сначала оформляется как гипотеза и проверяется отдельным прогоном.

## Порядок

1. **Спецификация** по `references/spec-template.md`. Заполнить целиком до первого
   расчёта. Сохранить файл и его хэш (`sha256sum`).
2. **Прогон.** Скрипт или запрос пишет сырые числа в артефакт (csv/json). Артефакт
   не правится руками.
3. **Рабочий отчёт** по `references/run-report-template.md`. Правило из спеки
   переносится дословно, в него подставляются числа, из подстановки следует вердикт.
4. **Проверка формата:** `python scripts/check_run_report.py <отчёт>.run.md`.
   Код 0 значит, что форматные ворота пройдены. Это проверка формы, а не истины.
5. **Заявка в реестр** — блок JSON в §5.2 отчёта. Дальше работает `insight-registry`.

## Жёсткие правила

- Правило решения не меняется после просмотра результатов. Если пороги были
  выбраны неудачно, создаётся новая версия спеки с пометкой «v2, причина»;
  прежний прогон остаётся в истории со своим вердиктом.
- Вердикт `open` — полноценный исход. Его нельзя «округлять» до supported.
- Утверждение должно быть опровержимым: направление эффекта, величина или порог,
  условие. «Изучить динамику НВВ» утверждением не считается.
- Входные данные описываются публичным именем выборки, числом документов,
  периодом и хэшем исходных файлов. Пути и команды остаются в §1 отчёта.
- Исходный корпус только читается. Все производные файлы пишутся в отдельный каталог. Состояние корпуса
  фиксируется снимком (`corpus-manifest`), его `corpus_hash` попадает в спецификацию и отчёт.
- Любая арифметика в §2–§3 — через `ru-corpus calc` или `ru-corpus aggregate`; число, которого нет на странице
  документа, проверяется `ru-corpus number`. Сравнение «больше» и «растёт» без расчёта не принимается.
- Перед сравнением периодов выполняется `period-comparability check`. Блокирующий разрыв допускает только
  вердикт `open`.
- Опорные документы получают класс (`source-classes`); точный вывод на слабом источнике не принимается.
- В §4 («чего прогон не доказывает») должно быть минимум два пункта. Типовые:
  неполнота раскрытия, смена методологии формы между годами, выборка по доступным
  документам, разные единицы измерения, один период вместо ряда.
- Число в выводе без единицы, периода и выборки не принимается.

## Как выбирать форму вывода

| Ситуация в §3–§4 | Что записывать |
|---|---|
| Порог пройден с запасом, выборка полная, угрозы второстепенны | `supported`/`refuted`, `definite` |
| Порог пройден, но запас мал или есть существенная угроза | тот же вердикт, но `tentative` |
| Метрика у порога или данных заметно меньше плана | `open`, `tentative`, следующий шаг в открытые вопросы |
| Выяснилось, что метрика измеряет не то | не вердикт; методический вывод и новая спека |
| Прогон упал или данных нет | отчёт со статусом «не завершён», инсайтов нет |

## Связанные навыки

`corpus-manifest` (снимок и хэш корпуса), `period-comparability` (разрывы между периодами),
`source-classes` (класс и качество источника), `insight-registry` (запись выводов и перепроверка),
`leak-check` (проверка перед публикацией), `cost-log` (затраты прогона).

## Форматные ворота `.run.md`

Скрипт проверяет:

1. §0 «Привязка» содержит id гипотезы, id спеки и её хэш в обратных кавычках.
2. §3 содержит строку правила и строку «Факт».
3. §5.1 содержит ровно одну строку вердикта вида
   `` `<id>` → <текст> **supported|refuted|open** ``.
4. §5.2 содержит ровно один блок ```json с массивом из 0–3 инсайтов.
5. В §4 не меньше двух пунктов списка.
6. Вердикт в §5.1 совпадает с вердиктом из §3 (строка «Правило даёт»).
7. §0 содержит строку «Хэш корпуса» с шестнадцатеричным хэшем (не короче 12 знаков).
8. §0 содержит строку «Сопоставимость периодов» со значением `пройдена`, `после пересчёта` или
   `не нужна`.

Заготовки лежат в `references/`.
