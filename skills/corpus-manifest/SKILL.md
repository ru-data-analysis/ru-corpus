# Манифест корпуса

Вывод по корпусу верен для тех файлов, по которым он получен. Манифест превращает «корпус» в
проверяемую величину: список файлов с SHA-256 и один итоговый хэш корпуса `corpus_hash`.

Реестр источников ядра (`registry.csv`, колонки `rel_path`, `sha256`) отвечает на вопрос «что лежит в
индексе сейчас». Этот навык отвечает на другие вопросы: «что изменилось с прошлого раза» и «тот же ли это
корпус, по которому был сделан вывод».

## Команды

```bash
python scripts/manifest.py snapshot ./документы --out снимки/2026-11-22.json [--ext pdf,docx,xlsx]
python scripts/manifest.py from-csv demo/corpus/MANIFEST.csv --out снимки/demo.json
python scripts/manifest.py diff снимки/старый.json снимки/новый.json [--json]
python scripts/manifest.py verify снимки/новый.json ./документы
python scripts/manifest.py hash снимки/новый.json
```

- `snapshot` обходит каталог, считает SHA-256 каждого файла, пишет JSON. Путь `--out` не может лежать внутри
  корпуса: корпус только читается.
- `from-csv` строит снимок из готового реестра (демо `MANIFEST.csv`, `registry.csv` индекса) без чтения файлов.
  Нужны колонки пути (`rel_path`, `файл` или `path`) и `sha256`.
- `diff` печатает добавленные, удалённые, изменённые и переименованные (тот же хэш, другой путь) файлы.
  Код возврата 0 — корпус тот же, 1 — есть различия.
- `verify` заново считает хэши файлов и сверяет со снимком; расхождение означает, что файл правили
  после съёмки.
- `hash` печатает `corpus_hash`; его записывают в §1 рабочего отчёта (навык `analysis-spec-first`).

## Когда снимать

1. Перед первым прогоном по гипотезе; хэш идёт в спецификацию и отчёт.
2. После каждого обновления корпуса (новые акты, замена файла); затем `diff` со старым снимком.
3. Перед публикацией вывода: `verify`, чтобы убедиться, что исходники не менялись.

После `diff` запустите `python ../insight-registry/scripts/recheck.py` (см. `insight-registry`): он
пометит выводы, чьи документы изменились или исчезли.

## Что считается снимком

`corpus_hash` — SHA-256 от отсортированных строк `путь<TAB>sha256`. Он не зависит от времени съёмки и
порядка обхода. Пути хранятся относительно корня, с `/`. Скрытые файлы и каталоги (`.git`, `.DS_Store`,
индекс `.kb`, `index`) пропускаются.

## Ограничения

- Хэш подтверждает совпадение байтов, а не смысла: пересохранённый PDF с тем же текстом даст другой хэш.
  Для PDF с датами создания в метаданных используйте столбец реестра без дат (в демо `sha256_без_дат_pdf`):
  `from-csv --hash-col sha256_без_дат_pdf`.
- Скрипт читает файлы целиком порциями по 1 МиБ; на очень больших корпусах первая съёмка идёт долго.
