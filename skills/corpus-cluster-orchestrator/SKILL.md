# Оркестратор кластеризации документов

Задача: по **выбранному набору документов** и **одному вопросу** получить кластеры
(какие документы отвечают на вопрос одним и тем же способом) и проверяемый обзор.
Протокол в три фазы плюс критика. Проверяемость важнее красоты: каждое утверждение
в обзоре прослеживается до цитаты и места в документе.

## Когда применять

- Нужно сгруппировать акты или раскрытые документы по теме («как документы определяют X»).
- Набор слишком велик для одного прохода, но каждый документ нужно читать.
- Не применять для чисто числовых таблиц: там нужен расчёт, а не чтение.

## Роли

| Роль | Сколько | Видит | Выдаёт |
|---|---|---|---|
| Воркер | 3–4 (`min(4, n)` при малом наборе) | свои документы и вопрос | находки с цитатами и местом |
| Воркер, обмен | те же | свои документы и **чужие находки** (не тексты) | суждения о сходстве |
| Оркестратор | 1 | все находки и таблица сходства | кластеры, членство, черновик обзора |
| Критик | 1 | вопрос и черновик обзора | оценка 1–10 и конкретные замечания |
| Ревизор | 1 на раунд | черновик и замечания | исправленный обзор |

Один документ достаётся ровно одному воркеру. Воркеры друг с другом не общаются,
кроме фазы обмена. Роли выполняют разные субагенты; если субагентов нет, это
нужно сказать, а результат пометить как однопроходный.

## Хранение

```
clusters/<run_id>/
  manifest.json            # вопрос, хэш вопроса, список документов с хэшами, разбиение, зерно
  workers/wNN_findings.json
  workers/wNN_judgments.json
  findings.json            # слитые находки
  similarity.json
  clusters.json
  overview.draft.md
  critique.json            # раунды: оценка и замечания
  overview.md              # итог после ревизии
```

`run_id = <первые 12 hex SHA-256 от нормализованного вопроса>_<UTC-метка>`.

## Фаза A. Разбиение

```bash
python scripts/partition.py docs.csv "вопрос" --workers 4 --out clusters
```

`docs.csv` — колонки `doc_id,title,path,sha256` (допускаются пустые `sha256`, скрипт
посчитает по `path`). Разбиение детерминировано: зерно берётся из хэша вопроса. Скрипт
пишет `manifest.json` и по файлу назначения на воркера.

## Фаза B. Находки

Каждый воркер отвечает на вопрос **только по тексту своих документов** и выдаёт JSON:

```json
{
  "worker_id": "w01",
  "findings": [
    {
      "doc_id": "…",
      "answer": "1–3 предложения: что документ говорит по вопросу",
      "approach": "в чём способ решения или позиция",
      "requisites": {"вид": "…", "номер": "…", "дата": "…", "статус": "действует|утратил силу|неизвестно"},
      "quotes": [
        {"text": "дословная цитата", "locator": "стр. 12, п. 3.4", "proves": "что подтверждает"}
      ],
      "not_found": false
    }
  ]
}
```

Правила воркера:

- Цитата дословная и короче абзаца; без места (страница, пункт, строка) не принимается.
- Нет ответа в документе — `not_found: true` и пустые цитаты. Придумывать нельзя.
- Реквизиты берутся из текста документа. Если их там нет, ставится «неизвестно».
- Утверждение без цитаты в находку не попадает.

## Фаза C. Обмен

Каждому воркеру передаются находки остальных (ответы, подходы, цитаты, **без** полных
текстов). Воркер для каждой чужой находки отвечает: похожа ли она на что-то из его
документов, насколько (`high|medium|low|none`), и чем именно (указать свой документ и
общий признак). Результат — `wNN_judgments.json`, слитая матрица — `similarity.json`.

## Фаза D. Кластеры

Оркестратор строит кластеры по `similarity.json` и находкам:

- кластер = общий способ ответа на вопрос, а не общая тема слов;
- у кластера: название (≤8 слов), определение одной фразой, список `doc_id`,
  представительные цитаты (минимум по одной от двух документов, если есть);
- документ может входить в несколько кластеров, это записывается явно;
- документы с `not_found` лежат в отдельной группе, не в кластерах;
- каждый кластер сопровождается слабым местом: чем он может оказаться неверным.

Черновик обзора `overview.draft.md`: 2–5 абзацев, только факты из находок, у каждого
утверждения ссылка на `doc_id` и место.

## Фаза E. Критика и ревизия

Критик получает вопрос и черновик и возвращает:

```json
{"round": 1, "score": 7, "answers_question": "полностью|частично|нет",
 "comments": [{"issue": "…", "where": "абзац 2", "fix": "что сделать"}]}
```

Ревизор исправляет каждое замечание и перечисляет, что изменил. Раундов не больше
двух; если оценка ниже 6 после второго, итог маркируется «не готов» и причины
остаются в `critique.json`.

## Проверка итога

Автоматическая часть: `python scripts/verify_quotes.py clusters/<run_id> --text-dir texts`
(тексты лежат в `texts/<doc_id>.txt`; PDF и сканы предварительно переводятся в текст).
Скрипт ловит выдуманные цитаты, цитаты без места и документ, попавший двум воркерам.

- Каждая цитата найдена в тексте источника (поиск подстроки после нормализации пробелов).
- Нет документа, назначенного двум воркерам.
- Все `doc_id` из обзора есть в `manifest.json`.
- Число документов в кластерах + группа «нет ответа» равно размеру набора.
- Реквизиты со статусом «неизвестно» перечислены в конце обзора отдельным списком.

Если исходники документов защищены грифом, все фазы выполняются локально, а наружу
выходит только `overview.md` без цитат, если владелец не разрешил иное.
