# Проверяемая аналитика по корпусу документов

Методика для агента, который отвечает на вопросы по корпусу русскоязычных документов. Ответ ценен, только
если каждое утверждение можно проверить по первичному документу: у цифры есть файл, страница, единицы и период.

Инструменты — `corpus_search`, `corpus_doc`, `corpus_page`, `corpus_table`, `corpus_number`,
`corpus_aggregate`, `corpus_calc` (плагин `dsh-ru-corpus`) или те же подкоманды `ru-corpus search|doc|page|table|number|aggregate|calc`
в консоли. Корпус должен быть проиндексирован (`ru-corpus init`, `ru-corpus index`; см. навык `russian-corpus-search`).
Отраслевые правила и ловушки — в справочниках `references/`; сейчас там `tso-disclosure.md`.

## Шаг 0. Проверка среды

Вызвать `corpus_doc` с `find` по слову из названия любого документа. Ответ «нет corpus.toml» или «команда не найдена» —
корпус не подключён: сказать об этом и остановиться, не отвечая по памяти.

## Шаг 1. Разложить вопрос (до любого поиска)

Составить таблицу: **подвопрос → документ, где должен быть ответ → период → единицы**. Для вопроса из
больше чем трёх подвопросов — по отдельному подагенту (если они есть) на подвопрос; каждый возвращает
таблицу «утверждение — цифра — doc — страница — проверено».

## Шаг 2. Поиск и чтение страницы

1. `corpus_doc` с `find` (вид документа + год) — найти документ и его реквизиты: год из шапки, дату и номер акта,
   период. Производные отчёты и сводки — вторичный слой.
2. `corpus_search` — где в документах ответ: файл, страница, раздел, фрагмент. `verdict: "в корпусе нет"` —
   доказательств нет. Запрос из одного числа ищет его по всем страницам без учёта разделителей тысяч.
3. `corpus_page` — прочитать страницу целиком; `ocr: true` — страница распознана со скана.

Источник ответа — только корпус через `corpus_*`. Не искать готовые ответы, эталоны и прошлые отчёты в
рабочих файлах (выводы, кэши, заметки, скрипты) через grep, glob или read: это не первичка. Не писать
одноразовый код для поиска и чтения документов; код — только для вычислений, которых нет среди инструментов.

## Шаг 3. Таблицы и итоги

- `corpus_table` — точная цифра из таблицы: подпись строки, год, уровень (если задан профилем), полугодие;
  в ответе якорь «стр., таблица, строка, графа».
- `corpus_aggregate` — итог по графе реестра или таблицы Excel/DOCX: сумма, число строк, среднее,
  отношение сумм двух граф (`column2`), фильтр строк (`where`). Если в источнике есть строка «Итого»,
  инструмент сверяет с ней, а не суммирует её; `warning` — итог неполный, так и писать.
- `corpus_calc` — любая другая арифметика: сумма нескольких чисел, разность, доля, темп
  (`"1 234,5 + 0,25"`, `"(120,5 - 100) / 100 * 100"`).

## Шаг 4. Проверка чисел

- Каждую цифру записывать сразу с doc, страницей, единицами, периодом, план или факт, с НДС или без.
- Перед ответом каждую цифру — `corpus_number`; `found: false` — цифру без пометки не ставить.
- **Никакой арифметики и сравнений в уме.** Любая сумма, разность, доля, темп — и в выводе, и в
  пояснениях, и в оговорках — только из `corpus_aggregate` или `corpus_calc`. Утверждения «сходится»,
  «равно», «больше на …» — тоже арифметика: сначала расчёт, потом вывод. Инструмент отказал —
  привести слагаемые с источниками и написать «сумма не вычислялась».
- **У каждой цифры документ и страница**, в том числе в побочных оговорках и сравнениях. Не знаешь
  документа — найди его `corpus_search` по самому числу или убери цифру.
- Суммы по графам — формула из поля `formula` и пометка «расчёт по строкам», если итога в источнике нет.

## Шаг 5. Сверка и противоречия

- Не смешивать: план и факт; с НДС и без НДС; тыс. и млн; редакции одного акта; отчётный период и период
  действия; год подписания и год действия.
- Цифра, найденная только во вторичной сводке, — «не подтверждено первичкой», а не факт.
- Скан: цифру сверять с текстовым источником тех же данных; нет такого — «скан, требует сверки».
- Расхождения между документами — отдельной таблицей с обоими источниками и причиной (редакция, период,
  единицы, округление).
- «В корпусе нет» — только по `verdict` из `corpus_search`; слабый или пустой ответ векторного поиска
  отсутствия не доказывает.

## Шаг 6. Проверяемый результат

Для записки или отчёта: `evidence_add` (content — `text` из `corpus_page`, origin — `origin`) для каждой использованной страницы →
`research_report` (утверждения привязаны к доказательствам, проверка побайтно) → `ledger_query`: нет `unverified` без пометки.
Если этих инструментов нет — та же дисциплина цитат в тексте: файл, страница, раздел у каждой цифры.

## Форма ответа

1. Итог — 2–4 предложения с ключевыми цифрами.
2. Таблица цифр: показатель — значение — единицы — период — источник (файл, стр., раздел).
3. Расхождения и оговорки.
4. Чего в корпусе нет и что не подтверждено.
5. Как проверить: вызовы `corpus_number` или путь к запечатанному отчёту.

## Самопроверка перед отправкой

- [ ] каждая цифра подтверждена `corpus_number`;
- [ ] у каждой ссылки есть файл, страница и раздел;
- [ ] указаны план или факт, единицы, период, редакция акта;
- [ ] нет выводов только из вторичных сводок без пометки;
- [ ] вычисления показаны формулой и сделаны инструментом;
- [ ] пробелы названы, а не заполнены.

## Общие ловушки

- Сканы без поворота теряют числа; проверяйте поле `ocr` и сверяйте цифры.
- Год в имени файла не равен году действия документа: смотрите реквизиты `corpus_doc`.
- Заголовок графы может содержать год, не совпадающий с периодом документа: период уточнять по тексту документа.
- Графа, объединённая по вертикали, наследует год соседней: смотрите якорь ячейки, а не только поле `year`.
- Таблицы Excel с пустыми ячейками: смещение столбцов проверяйте по полю `unaligned_rows` и по первой и последней строке из `corpus_aggregate`.
