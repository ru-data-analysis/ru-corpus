# Реестр инсайтов

Реестр отвечает на вопрос «что мы уже знаем и насколько твёрдо». Он состоит из
двух слоёв, которые нельзя смешивать.

| Слой | Где | Кто пишет |
|---|---|---|
| Автоген | `registry/insights.json` → `KNOWLEDGE.md` | только скрипт `registry.py` |
| Курируемый | `knowledge/NN-тема.md` | агент или человек |

Автоген руками не править: он перезаписывается. Связи между выводами,
противоречия и пределы применимости пишутся только в курируемый слой.

## Схема записи

| Поле | Правила |
|---|---|
| `id` | назначает скрипт: `i-<source_id>-<n>` |
| `topic` | тема или метод, внутри которой лежит вывод; не больше 3 записей на тему |
| `question` | один вопрос, понятный без контекста проекта: без аббревиатур и названий метрик |
| `narrative` | 2–4 предложения человеческим языком |
| `answer` | техническая запись: числа, единицы, период, выборка — только здесь |
| `certainty` | `definite` — есть критерий, воспроизводимый результат, прямой ответ; `tentative` — мало данных, противоречия, промежуточные метрики |
| `importance` | 1 — побочный факт, 3 — полезное уточнение, 5 — меняет решение по теме |
| `source_id` | id прогона или отчёта, из которого вывод получен |
| `evidence` | список `{path, locator, sha256}`: файл, место (страница, пункт, строка) и хэш файла на момент прогона (берётся из снимка `corpus-manifest`) |
| `verdict` | вердикт гипотезы из §5.1, если есть |
| `status` | отсутствует, пока вывод актуален; `needs_recheck` ставит `recheck.py` |

## Команды

```bash
python scripts/registry.py validate registry/insights.json
python scripts/registry.py ingest   registry/insights.json report.run.md --topic <тема> [--dry-run]
python scripts/registry.py render   registry/insights.json KNOWLEDGE.md [--knowledge-dir knowledge]
python scripts/registry.py list     registry/insights.json [--topic <тема>]
python scripts/recheck.py          registry/insights.json снимки/новый.json [--write]
```

- `ingest` берёт блок §5.2 отчёта (после проверки `check_run_report.py`), присваивает
  записям `source_id` из §0 отчёта и **заменяет** все прежние записи этого же источника.
  Повторная загрузка того же отчёта ничего не меняет.
- Если у темы уже 3 записи и приходит новая из другого источника, скрипт отказывает и
  называет запись с минимальной важностью: её нужно обновить или объединить вручную.
- `render` пересобирает `KNOWLEDGE.md`: таблица по темам, предварительные выводы помечены,
  в конце оглавление курируемых документов.

- `recheck.py` сверяет хэши документов из `evidence` со свежим снимком корпуса (`corpus-manifest`).
  Вывод, чей документ изменился или исчез, получает `status: needs_recheck`; `render` показывает отметку
  «⚠ перепроверить». Вывод не удаляется и не меняет точность: решает человек после повторного прогона.
  Повторный `ingest` отчёта того же источника снимает отметку, потому что запись заменяется целиком.
  Код возврата 1, если затронутые выводы найдены.
- Перед `ingest` точных выводов (`certainty: definite`) выполните ворота `source-classes gate`: точный вывод
  не может опираться на пересказ, копию без сверки или шумный слой распознавания.

## Порядок работы после прогона

1. Убедиться, что отчёт прошёл `check_run_report.py`.
2. Выполнить `ingest --dry-run`, посмотреть, что изменится, затем без `--dry-run`.
3. Прогнать `question` и `narrative` через вопрос читателя: понятно ли без глоссария?
4. `render`.
5. Если с прошлого курирования добавилось три и больше вывода по одной теме или есть
   противоречие — выполнить курирование.

## Курирование (глубокий слой)

Источники: реестр, отчёты-основания, разделы «Чего прогон не доказывает».
Документ `knowledge/NN-тема.md` по форме:

- `# Заголовок`, затем первый абзац — сводка в 1–2 предложения (она попадает в оглавление);
- тезис = утверждение + числа + ссылка на отчёт;
- обязательные подразделы: «Связки», «Противоречия», «Пределы применимости»,
  «Открытые вопросы»;
- противоречие записывается явно: «в прогоне A получено X, в прогоне B при других
  условиях — Y; граница не установлена». Сглаживать нельзя;
- `tentative` помечать в тексте как предварительное;
- не пересказывать реестр: документ нужен для связей и смысла.

## Чего не делать

- Не записывать в реестр вывод без отчёта и без числа.
- Не повышать `certainty` без нового прогона.
- Не удалять записи, отменённые новым прогоном: старая запись заменяется только
  повторным `ingest` того же источника; отказ от вывода фиксируется в курируемом
  документе.
