# Проверка на утечки

`scripts/scrub_check.py` в корне репозитория проверяет, что в **репозитории** нет привязок к частному
корпусу. Этот навык проверяет другое: **результаты анализа**, которые собираются вне репозитория и могут
унести из закрытого корпуса гриф, название, длинную цитату или путь рабочей машины.

## Запуск

```bash
python scripts/leak_check.py отчёты/ clusters/ registry/insights.json \
       [--patterns ~/закрытые-шаблоны.txt] [--closed ~/закрытые-документы.txt] [--max-quote-words 40]
```

Проверяются текстовые файлы (`.md`, `.txt`, `.json`, `.csv`, `.tsv`, `.toml`) в указанных путях. Код
возврата 1, если что-то найдено. Найденный фрагмент в вывод **не печатается**: только файл, строка и правило,
чтобы журнал проверки сам не стал утечкой.

## Что проверяется всегда

| Правило | Пример |
|---|---|
| гриф | слова «конфиденциально», «для служебного пользования», «ДСП», «коммерческая тайна» |
| путь рабочей машины | домашний каталог пользователя в macOS и Windows |
| ключ или токен | ключи API, токены доступа, переменные с секретом |
| длинная цитата | цитата в `quotes[].text` длиннее порога слов (по умолчанию 40) |

## Что задаёт владелец корпуса

Два файла, которые **не коммитятся** в открытый репозиторий, потому что сами раскрывают закрытое:

- `--patterns`: по одной строке `название<TAB>регулярное выражение` или просто регулярное выражение;
  строки с `#` — комментарии. Сюда идут названия закрытых организаций, внутренние коды документов, ИНН.
- `--closed`: список закрытых документов (имя файла, `doc_id` или начало SHA-256), по одному в строке.
  Любое упоминание из списка в результате — нарушение.

Хранить эти файлы нужно вне репозитория и вне публикуемых каталогов.

## Когда запускать

1. Перед `git commit` результатов, которые идут в открытый репозиторий.
2. Перед передачей отчёта или находок во внешнюю модель или сервис.
3. После `corpus-cluster-orchestrator` и `insight-registry render`, если корпус закрытый.

Чистая проверка не доказывает отсутствие утечки: она ловит перечисленное, а не смысл. Перед публикацией
всё равно нужно прочитать итоговый текст.
