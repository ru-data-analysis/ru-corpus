# Классы источников

Одна и та же цифра весит по-разному в зависимости от того, откуда взят документ. Навык задаёт две
независимые оси и одну проверку.

## Оси

**Происхождение** (`origin_class`):

| Класс | Что это |
|---|---|
| `A` | первоисточник: файл с официального сайта органа, издавшего акт |
| `B` | копия акта в правовой базе или у третьей стороны, реквизиты сверены с первоисточником |
| `C` | пересказ, новость, аналитическая сводка, любой производный текст |
| `?` | не определён: хост не входит ни в один список; решение принимает человек |

**Качество текста** (`quality`): `T` — родной текстовый слой; `O` — текст получен распознаванием
скана; `N` — встроенный слой распознавания шумный (цифры могли исказиться); `?` — неизвестно.

Правила по умолчанию — `references/classes.default.json`: списки хостов для `A`, `B`, `C`. Свои правила
передаются через `--rules`. Хост, которого нет в списках, получает `?`, а не `C`: автоматически снижать класс
и автоматически поднимать его одинаково опасно. Ручные решения записываются в `--overrides`
(`path,class,reason`), причина обязательна.

## Команды

```bash
python scripts/source_class.py classify demo/corpus/MANIFEST.csv --out classes.csv \
       [--rules my-rules.json] [--overrides overrides.csv]
python scripts/source_class.py summary classes.csv
python scripts/source_class.py gate registry/insights.json classes.csv [--allow-ocr] [--allow-class B]
```

`classify` читает реестр с колонками пути (`файл` или `rel_path`), `url_источника` или `url` и
`текстовый_слой` (как в демо `MANIFEST.csv`); недостающие колонки дают `?`.

## Ворота для точных выводов

`gate` проверяет реестр выводов (`insight-registry`): запись с `certainty: definite` обязана иметь
`evidence`, и каждый документ из `evidence` должен иметь класс `A` и качество `T`. Параметры
`--allow-class B` и `--allow-ocr` расширяют допуск осознанно. Нарушение значит одно из двух:
понизить вывод до `tentative` или найти первоисточник. Код возврата 1 при нарушениях.

Для `tentative`-выводов ворота только предупреждают о классах `?`, `C` и качестве `N`.

## Порядок

1. Снять манифест корпуса (`corpus-manifest`) и выполнить `classify`.
2. Разобрать все `?`: добавить хост в правила или записать решение в `overrides.csv`.
3. Перед `insight-registry ingest` и перед публикацией выводов выполнить `gate`.
4. В отчёте (`analysis-spec-first`) указать класс опорных документов в таблице §2.
